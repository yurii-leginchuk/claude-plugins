# QC-плагин, третья корзина: сравнение с Figma и копи-доком, команда /qc-page

Дата: 2026-08-02
Статус: согласовано, готово к планированию реализации
Предшественники: `2026-08-01-qc-plugin-bucket1-design.md` (статический движок),
`2026-08-01-qc-browser-pass-design.md` (браузерный проход, влит в main)

## Контекст

Движок закрывает то, что видно по самой странице: 22 статических правила по HTML и 9 браузерных
по отрисованной странице. Но самая ценная для агентства группа дефектов — расхождения с
источниками истины: копирайт-доком (Google Doc) и макетом Figma. В таксономии это вся группа A
(секции, вёрстка, цвета, картинки, количество элементов, типографика) и H2 (текст не совпадает с
копи-доком). Спека второй корзины отложила её сюда третьей корзиной, вместе с командой
`/qc-page` — той самой, ради которой QC одной страницы и затевался.

Прототип уже существует: личный скилл `~/.claude/skills/qc-page` делает это сравнение целиком
агентно — добывает док и Figma через браузер, сравнивает суждением модели, публикует
Artifact-отчёт. Он работает, но ничего в нём не тестируется и не повторяется, а пословный дифф
текста модель делает хуже и дороже, чем алгоритм. Зато он накопил знание о граблях: login-wall
Figma, приватные доки, view-only файлы, бот-челленджи — всё это переносится в новый скилл.

## Решения, принятые при обсуждении

| Вопрос | Решение |
|---|---|
| Состав корзины | Детерминированные reference-правила в движке **плюс** скилл `/qc-page` в плагине |
| Откуда данные Figma | Агентно через Figma MCP; движок в сеть не ходит. REST API с токеном отклонён |
| GBP-проверки личного скилла | Берутся целиком: плагинный `/qc-page` полностью заменяет личный скилл |
| Где граница детерминизма | H2, A1, A5, A6, A3 — правила движка; A2, A4 (визуальное суждение) и GBP — агентная часть скилла |
| Как агентные находки попадают в отчёт | Скилл пишет их в `agentic.jsonl` снапшота, `qc audit` сливает четыре источника в один отчёт |

## Архитектура

### Поток данных

```
Скилл /qc-page (агент)                        Движок (детерминированно, офлайн)
──────────────────────                        ─────────────────────────────────
копи-док: curl export?format=md  ──┐
Figma MCP: metadata + screenshot ──┼─►  qc refs <page-url> --copy copy.md
  → figma.json + renders/*.png ────┘        --figma figma.json [--renders dir]
                                            (валидирует и кладёт в снапшот)
A2/A4 визуально + GBP  ────────────►  agentic.jsonl (тот же формат finding)
                                      qc audit --page <url>
                                        → static + browser + reference + agentic
```

### Команды

```
qc refs <page-url> --copy <файл> --figma <файл> [--renders <дир>]   # установить референсы
qc audit  <вход> [--page <url>]     # + reference- и agentic-находки, если референсы есть
qc browse <вход> [--page <url>]     # + снятие styles.jsonl при наличии референсов
```

- `--page <url>` — режим одной страницы для audit и browse: обходится и браузерится только она,
  отчёт по ней. Нужен, потому что `/qc-page` работает по одной странице, а референсы привязаны
  к странице, не к сайту.
- `qc refs` валидирует форматы на входе (схему `figma.json`, непустой `copy.md`) и раскладывает
  в снапшот. Кривой файл отклоняется с внятной ошибкой — агент пересобирает и повторяет.

### Снапшот

```
~/.qc-cache/<host>/
  references/<page-slug>/
    copy.md            # сырой экспорт Google Doc, движок нормализует сам
    figma.json         # структура макета, собранная скиллом из данных Figma MCP
    renders/*.png      # рендеры секций Figma — для агентного A2/A4 и пар в отчёте
  agentic.jsonl        # агентные находки скилла, по строке на находку
  styles.jsonl         # вычисленные стили текстовых узлов, пишет browse
```

Кэш-слой (`crawl/store.js`) расширяется этими файлами; существующая структура не меняется.

### Правила

Reference-правила живут в `src/rules/reference/` — по файлу на правило, третий загрузчик по
образцу `browser-index.js`. Статический и браузерный загрузчики не трогаются. Правила выполняются
внутри `qc audit`, только когда для страницы есть референсы; сеть им не нужна — всё из файлов.

Для A3/A6 нужны вычисленные стили, которых нет в сыром HTML. Их снимает **browse**: при наличии
референсов он дополнительно пишет `styles.jsonl` — для каждого текстового узла нормализованный
текст, font-size, font-weight, цвет. Правила A3/A6 затем сравнивают его с `figma.json` статически.
Так правила остаются простыми файлами, а браузер — только сборщиком фактов.

## Форматы референсов

**`copy.md`** — сырой экспорт Google Doc (`export?format=md`). Движок сам нормализует его в
упорядоченные блоки `{type: h1|h2|h3|p|li|cta|faq-q|faq-a, text}` упрощённым md-парсером без
новых зависимостей (заголовки, абзацы, списки, bold-строки как кандидаты в CTA; FAQ — по
заголовку «FAQ»/«Frequently Asked»). Скилл ничего не переписывает — меньше места для агентных
искажений, а нормализатор тестируется на реальном экспорте.

**`figma.json`** — производит скилл из данных Figma MCP; движок валидирует схему при `qc refs`:

```json
{
  "source": "<figma-url>",
  "frame": "Home 1440",
  "sections": [
    {
      "order": 1,
      "name": "Hero",
      "heading": "Deep Cleaning Services in NYC",
      "texts": [{ "text": "…", "fontSize": 60, "fontWeight": 700, "color": "#1A2B3C" }],
      "repeating": { "itemName": "card", "count": 4 },
      "render": "renders/01-hero.png"
    }
  ]
}
```

Обязательны только `source`, `sections[].order`, `sections[].heading`. Правила читают лишь то,
что заполнено: нет `texts` — молчат A6/A3 по секции, нет `repeating` — молчит A5, нет `render` —
секция без пары в отчёте. Это защита от шума при неполных данных из MCP.

## Пять reference-правил

| ID | Проверка | Severity | Confidence |
|---|---|---|---|
| `H2` | Каждый блок копи-дока найден на странице в том же порядке (выравнивание блоков — LCS); внутри изменённого блока — пословный дифф. Пропавший блок и изменённый текст — находка с диффом. Лишний текст страницы (меню, футер, куки-баннер) не флагуется | major | high |
| `A1` | Секции `figma.json` ↔ секции страницы по нормализованному совпадению заголовков: отсутствует, лишняя, порядок нарушен | major | heuristic |
| `A5` | Для сматченной секции: число повторяющихся элементов в DOM не равно `repeating.count` | major | heuristic |
| `A6` | Текстовые узлы Figma ↔ DOM по совпадающему нормализованному тексту (join-ключ — сам текст); сравнение font-size и font-weight из `styles.jsonl` с допуском ±1px | minor | heuristic |
| `A3` | Тот же маппинг; сравнение цвета текста с порогом ΔE, чтобы не флагать #1a1a1a против #1b1b1b | minor | heuristic |

Заголовки правил — по-русски, находки несут селектор и короткие `found`/`expected`, без полного
HTML — как во всех существующих правилах. Все A-правила — `heuristic` до живой калибровки: обе
предыдущие корзины показали, что пороги, назначенные до прогона по реальной странице, дают шум.
A2 (секция свёрстана иначе) и A4 (другая картинка) в движок не идут — это принципиально
визуальное суждение, агентная часть скилла.

## Скилл /qc-page

Живёт в `plugins/qc/skills/qc-page/`; личный скилл — донор текстов (рубрика, GBP-чеклист,
fallback-цепочки). Последовательность:

1. Классифицировать аргументы по паттернам URL независимо от порядка: Google Doc, Figma, Maps
   (опциональный GBP), остальное — страница под QC. Отсутствующий источник — спросить с опцией
   «пропустить»; пропуск отключает его проверки, в отчёте это «Not checked», никогда молча.
2. Добыть копи-док: `export?format=md`, при провале — `format=html`/`format=txt`, при провале —
   браузер пользователя, иначе — дименсия «Not checked».
3. Добыть Figma через Figma MCP (`get_metadata` — структура, `get_screenshot` — рендеры секций);
   при недоступности MCP — fallback на Chrome-скриншоты из личного скилла (тогда движковые
   A-правила без `figma.json` молчат, работает только агентная часть). Собрать `figma.json`.
4. `qc refs <page-url> --copy … --figma … --renders …`, затем `qc audit --page` и
   `qc browse --page`.
5. Агентная часть: сравнить рендеры Figma с кропами browse — A2/A4; GBP-проверки по портированному
   чеклисту. Находки — в `agentic.jsonl` в формате движкового finding с пометкой источника.
6. Финальный `qc audit --page` собирает единый отчёт; скилл публикует его Artifact'ом и даёт
   резюме в чат: вердикт, счёт по severity, топ находок, путь к отчёту.

## Отчёт

Reference- и agentic-находки вливаются в существующий HTML/JSON-отчёт как третий и четвёртый
источники — тем же слиянием, что и браузерные. Шапка покрытия показывает, какие референсы заданы
и когда сняты. К A2/A4-находкам прикладываются пары «рендер Figma / кроп страницы» по образцу
браузерных скриншотов. В счёте — `distinct`, не `counts`, как и раньше.

## Обработка ошибок

- Нет референсов — audit работает как раньше; в шапке отчёта «референсы не заданы».
- Битый `figma.json` — `qc refs` отклоняет с перечнем нарушений схемы; агент пересобирает.
- Кривая строка в `agentic.jsonl` — строка пропускается, в отчёте warning; audit не падает.
- Референсы старше снапшота или наоборот — в шапке отчёта предупреждение о рассинхроне дат.

## Тестирование

Офлайн-фикстуры «copy.md + figma.json + HTML с заведомыми расхождениями» на каждое правило и в
обе стороны: случай-нарушение и случай-норма. Md-нормализатор тестируется на реальном экспорте
Google Doc, положенном в фикстуры. Для A3/A6 — фикстурный `styles.jsonl` плюс браузерный тест,
что browse его корректно снимает (локальный сервер, как в тестах второй корзины). `npm test` —
по-прежнему bare `node --test`, интернет тестам запрещён.

Финальная задача плана — живой прогон на реальной странице с настоящим макетом Figma и копи-доком,
калибровка порогов (ΔE, допуск px, матчинг заголовков) с записью в calibration log
`plugins/qc/references/taxonomy.md`, как в корзинах 1–2.

## Границы этой итерации

Не входит и делается позже:

- кросс-страничная консистентность (B1, B2, F2, I12) — по-прежнему ждёт накопленной статистики;
- функциональные проверки JetPopup, слайдеров и фильтров (группа K);
- выгрузка находок в Asana;
- пиксельное сравнение скриншотов в движке (pixelmatch и т.п.) — отклонено: новая зависимость и
  шум, визуальное сравнение остаётся агентным;
- удаление личного скилла `~/.claude/skills/qc-page` — только после того, как плагинный пройдёт
  живой прогон.
