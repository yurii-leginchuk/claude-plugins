# QC-плагин, вторая корзина: браузерный проход

Дата: 2026-08-01
Статус: согласовано, готово к планированию реализации
Предшественник: `2026-08-01-qc-plugin-bucket1-design.md` (статический движок, влит в main)

## Контекст

Статический движок работает: 22 правила по сырому HTML, 394 теста, проверен на живом клиентском
сайте. Но целая группа дефектов из исследования им недоступна в принципе — их видно только когда
страница отрисована и измерена на конкретной ширине: горизонтальный скролл на мобильном, элемент,
вылезший за вьюпорт, отсутствие реакции на hover, недостаточный контраст, перекрытия.

В исходных 1000 правок это одна из самых массовых групп, и самая раздражающая для ревьюера:
её нельзя проверить чтением кода, только глазами на каждом брейкпоинте.

## Что показали реальные данные

Прогон первой корзины по 31-страничному клиентскому сайту дал два измерения, которые меняют
первоначальный замысел.

**Первое: страницы почти не группируются по шаблону.** Строгий отпечаток (набор ID контейнеров
Elementor + хеш скелета виджетов) дал **27 различных групп на 31 странице**. Elementor шарит
только шапку (`elementor-3374`) и футер (`elementor-3381`); контейнер контента у каждой страницы
свой — `5718`, `5254`, `7727`, `3616`. Сгруппировались лишь однотипные архивы: три поста блога и
три страницы категорий.

Значит замысел спеки первой корзины — «доказать шаблонность и проверить 1–2 представителя» — на
уровне страниц почти ничего не экономит.

**Второе: экономия есть, но на уровне регионов.** Шапка и футер идентичны на всех 31 странице, и
именно там сидели все повторяющиеся дефекты статического прогона (соцсети в футере, ссылка на
политику конфиденциальности). Отсюда решение: браузер открывает **каждую** страницу, но находка
внутри доказанно общего региона схлопывается в один дефект.

**Третье, практическое: дев-серверы медленные или мёртвые.** Из трёх проверенных дев-хостов один
ответил 200, два не ответили за 15 секунд. Это согласуется с прямой цитатой из правок: «the dev
server is weak». Для HTTP-обхода это терпимо, для браузера — определяющее ограничение.

## Решения, принятые при обсуждении

| Вопрос | Решение |
|---|---|
| Как гонять браузер при слабой группировке страниц | Открывать каждую страницу; схлопывать находки внутри доказанно общих регионов (шапка, футер) |
| Скриншоты | Точечные: кроп виновника с подсветкой, только на первое вхождение каждого различающегося дефекта |
| Долгий прогон на слабом сервере | Возобновляемый с чекпойнтами: результат каждой страницы пишется сразу, повторный запуск добирает недостающее |
| Где искать дефекты по ширине | Базовый набор плюс границы, вытащенные из `@media` самого сайта |
| Организация | Отдельная подкоманда `qc browse` поверх готового снапшота |
| Где выполняются правила | **В браузере**, а не в Node над извлечёнными фактами |

## Архитектура

### Команды

```
qc audit  <вход>            # статика (как сейчас)
qc browse <хост> [флаги]    # браузерный проход поверх готового снапшота
qc audit  <вход>            # повторно: сливает статику и браузер в один отчёт
```

`qc browse` **не краулит**. Список страниц берётся из снапшота, собранного `audit`. Аргумент — тот
же хост, что показывает `qc cache list`; принимается и полный URL, из которого хост извлекается.
Снапшота нет — команда отказывается работать и предлагает сначала запустить `audit`. Так браузер не
может разойтись со статикой в том, какие страницы считаются страницами сайта.

Флаги: `--breakpoints <список>`, `--pages <n>` (ограничить для быстрой итерации), `--force`
(перепроверить уже проверенное), `--concurrency <n>` (по умолчанию 2 — браузер тяжелее HTTP),
`--headed` (показать окно для отладки), `--only`/`--skip` по ID правил.

### Правила выполняются в браузере

`src/rules/browser/*.js` — самодостаточные функции без импортов Node. Все они собираются в один
скрипт, инжектируемый на страницу один раз на брейкпоинт, и возвращают **готовые находки**, а не
сырые измерения.

Осознанная плата: изменил правило — надо заново обойти страницы, переиграть сохранённые измерения
нельзя. Смягчается флагом `--pages` для итерации и тестами на локальных фикстурах.

Осознанная выгода, и она перевешивает: финальное ревью первой корзины нашло три Critical, и все три
возникли из-за того, что 21 правило из 22 тестировалось на рукописных объектах вместо реальной
страницы. Правила, выполняющиеся в настоящем браузере на настоящей вёрстке, от этого класса ошибок
защищены по построению.

### Порядок работы на странице

```
для каждой страницы:
  для каждой ширины:
    resize → goto → дождаться сети и шрифтов
    → медленный скролл до низа
    → снять CSS-анимации
    → evaluate(бандл правил) → находки
    → при первом вхождении дефекта: кроп виновника
  дописать строку в browser.jsonl
```

Два шага здесь не косметические, оба — из опыта прошлых прогонов:

- **медленный скролл до низа** обязателен, иначе lazy-картинки остаются `data:`-заглушками и
  правило X2 даёт ложные срабатывания на каждой странице;
- **снятие CSS-анимаций** обязательно, иначе элемент измеряется в промежуточном состоянии анимации
  и правила C2 и B6 плывут от прогона к прогону.

### Брейкпоинты

Базовый набор: 360, 768, 1024, 1440.

Плюс границы, извлечённые из `@media` самого сайта: каждая найденная ширина проверяется с обеих
сторон границы (`W` и `W-1`). Именно там живут дефекты из исследования — «от 1347px до 1189px
кнопка уезжает во вторую строку», «на 1230px убрать бургер». Круглые числа их не ловят.

Извлечение однократное на сайт: разбираются подключённые и инлайновые стили с главной страницы,
собираются значения `min-width`/`max-width`. Список ширин сохраняется в снапшот и переиспользуется,
переопределяется флагом `--breakpoints`.

Потолок — 10 ширин на сайт. Bootstrap, Elementor и тема вместе легко дают два десятка
медиазапросов, и без потолка время прогона умножается вдвое-втрое без пользы. При отборе
приоритет у границ, ближайших к базовому набору, и у самых часто встречающихся значений.
Отброшенные ширины перечисляются в отчёте — превышение фиксируется, а не проглатывается.

### Возобновляемость

`browser.jsonl` — по строке на пару «страница + набор ширин». Строка есть — страница проверена.
Повторный запуск читает файл, вычитает проверенное из списка и добирает остаток. `--force`
игнорирует уже сделанное.

Прогон, оборванный на середине, оставляет пригодный к использованию результат: отчёт строится по
тому, что есть, и **явно указывает**, сколько страниц ещё не проверено браузером. Молчаливая
неполнота недопустима — это тот же класс отказа, который в первой корзине был признан худшим.

### Когда страница не открывается

Два из трёх проверенных дев-хостов не ответили за 15 секунд, так что это не редкий случай, а
ожидаемый режим работы. Правила поведения:

- таймаут на страницу — 45 секунд (браузеру нужно больше, чем HTTP-обходу), одна повторная попытка;
- не открылась — записывается строка с причиной и пустым списком находок, обход продолжается;
  страница считается **проверенной неуспешно**, а не пропущенной, чтобы `--force` не требовался для
  повтора и чтобы она попала в отчётное покрытие как непроверенная;
- если подряд не открылось 10 страниц, прогон останавливается сам с внятным сообщением: скорее
  всего лёг сервер, и продолжать значит молотить в стену сорок пять секунд на страницу;
- число неоткрывшихся страниц и их список попадают в сводку и в шапку отчёта.

### Схлопывание по регионам

Регион доказывается измерением, а не предполагается. Контейнер Elementor, чей ID встречается более
чем на одной странице, считается общим регионом; его человекочитаемое имя берётся из класса
`elementor-location-*` (`header`, `footer`), иначе — сам ID.

Находка внутри общего региона получает этот регион в свою идентичность и схлопывается по нему, а не
по странице. Находка в контейнере, встреченном на одной странице, остаётся постраничной.

В отчёте это читается как «F1 · нет реакции на hover — футер, чинится один раз» вместо тридцати
одной одинаковой строки.

## Каталог правил

| ID | Проверка | Уровень | Уверенность |
|---|---|---|---|
| C1 | Горизонтальный скролл документа | Critical | high |
| C2 | Элемент шире вьюпорта, с указанием виновника | Major | high |
| X1 | Ошибки консоли и упавшие запросы | Major | high |
| X2 | Картинка не загрузилась или осталась `data:`-заглушкой | Major | high |
| F4 | `cursor:pointer` на неинтерактивном; его нет на интерактивном | Minor | high |
| F5 | Есть изменение на hover, но нет `transition` | Minor | high |
| F1 | У ссылки или кнопки нет визуальной реакции на `:hover` | Major | **heuristic** |
| J3 | Контраст текста ниже 4.5:1 (крупного — ниже 3:1) | Major | **heuristic** |
| B6 | Перекрытие или обрезка элементов | Major | **heuristic** |

Три эвристики выводятся отдельным блоком «требует взгляда» и **не влияют на вердикт**, пока не
будут откалиброваны на живом сайте. Основания: F1 определяется принудительной подстановкой
псевдокласса и на части тем даёт ложные срабатывания; J3 не умеет в фоновые изображения и
градиенты; B6 — самая шумная геометрическая эвристика.

Калибровка обязательна и запланирована как отдельный шаг после первого живого прогона — ровно как
это было с E1 и E3 в первой корзине, где живой прогон показал 95% шума и заставил переградуировать
оба правила.

## Отчёт

Браузерные находки вливаются в существующий отчёт и существующую группировку по правилу и дефекту.
Задействуется поле `breakpoint` схемы находки, до сих пор всегда `null`.

Скриншот — кроп виновника с подсветкой, только на первое вхождение каждого различающегося дефекта,
не на каждую страницу. Файлы кладутся в `~/.qc-cache/<хост>/shots/<идентичность-дефекта>.png`, имя
выводится из той же идентичности, по которой дефект схлопывается, — поэтому повторный прогон
переиспользует кроп, а не плодит копии. В отчёт встраивается как data-URI.

Бюджет размера как в первой корзине: при превышении порога публикации остаются только Critical и
Major, и в отчёте пишется, что часть изображений опущена.

Шапка отчёта дополняется покрытием: сколько страниц проверено браузером из общего числа, на каких
ширинах, и что осталось непроверенным.

## Структура

```
plugins/qc/engine/src/
  browser/
    run.js            # обход, брейкпоинты, чекпойнты, возобновление
    breakpoints.js    # базовый набор + извлечение границ из @media
    bundle.js         # сборка правил в один инжектируемый скрипт
    screenshot.js     # кроп виновника
    regions.js        # доказательство общих регионов
  rules/browser/
    C1-horizontal-scroll.js  C2-overflow.js  X1-console.js  X2-broken-images.js
    F1-hover.js  F4-cursor.js  F5-transition.js  J3-contrast.js  B6-overlap.js
plugins/qc/engine/test/browser/
  fixtures/*.html     # локальные страницы с заведомыми дефектами
  <rule>.test.js      # настоящий Chromium против локального сервера
```

Реестр правил сейчас грузит всё из `src/rules/static/` и по полю `engine` не фильтрует. Добавляется
второй загрузчик для `browser/`; статический путь не трогается.

Зависимость: `playwright` (Chromium, разовая загрузка около 150 МБ в папку движка). Становится
второй и последней зависимостью движка.

## Тестирование

Локальный http-сервер отдаёт HTML-фикстуры с заведомо внесёнными дефектами; тест поднимает
настоящий Chromium и проверяет находки. Медленнее юнит-тестов и требует установленного браузера —
принято сознательно, потому что именно этой проверки не хватило в первой корзине.

Для каждого правила обязательны оба направления: случай-нарушение и случай-норма. Отдельно
фиксируются два предусловия измерения — что после медленного скролла lazy-картинки загружены, и что
после снятия анимаций повторное измерение того же элемента даёт тот же результат.

## Границы этой итерации

Не входит и делается позже:

- сравнение с Figma и копи-доком (группы A и H2 таксономии) — третья корзина;
- кросс-страничная консистентность отступов и hover-цветов (B1, B2, F2, I12) — нужна накопленная
  статистика выбросов по сайту;
- функциональные проверки JetPopup, слайдеров и фильтров (группа K) — требуют сценариев
  взаимодействия, а не снимка состояния;
- выгрузка находок в Asana;
- проход по проду и команда `/qc-page` — переносятся сюда из первой корзины и делаются после того,
  как браузерные правила откалиброваны, иначе `/qc-page` унаследует некалиброванный шум.

## Открытые долги первой корзины, которые стоит закрыть попутно

Оба записаны при завершении первой корзины и близки к затрагиваемому коду:

- E4 молчит на задвоенном коде страны и отдаёт случай E5, из-за чего номер с некорректными
  разделителями падает из `major` в эвристику;
- баннер «снапшот старше 7 дней» недостижим, потому что снапшот старше 7 дней не переиспользуется;
  сообщение коммита `dc6889e` при этом утверждает обратное и должно быть исправлено.
